# NetScope V1.1 实现与验收说明（受控干预：结束进程）

当前本地代码版本为 `1.1.0`。按 [进程终止功能设计](进程终止功能设计.md) 完成首版受控干预：结束进程建议（只读评估）、请求关闭、强制结束与本地审计。此次实现未创建 GitHub Release。

## 功能范围

进程中心详情面板新增“结束进程建议”卡片与两个操作按钮：

- **结束建议**：选中进程后由只读检查器采集事实（关键标志、创建时间、路径、所有者 SID、会话、服务归属、主窗口、签名/发布者、监听端口数），纯规则引擎给出五级建议——`禁止结束 / 强烈不建议 / 可以结束但可能中断功能或丢失数据 / 通常可以结束 / 无法判断`，附证据清单、未知项与替代操作。
- **请求关闭**：向主窗口发送正常关闭请求，等待最多 10 秒确认退出；应用可保存或拒绝，请求不等于关闭成功。
- **列表行快捷强制结束**：概览"当前高影响进程"与进程中心的每行都有强制结束按钮（NetScope 自身不显示）。点击时对该进程按需只读评估：不允许的目标（禁止/强烈不建议/证据不足）不会执行任何动作，而是跳转到进程中心选中该行并用建议卡片说明原因；允许的目标走与详情面板完全相同的确认对话框与执行链——不存在绕过评估的第二条路径。
- **强制结束**：仅对 `Caution` 和 `UsuallyTerminable` 开放；使用最小权限 `PROCESS_TERMINATE | SYNCHRONIZE | PROCESS_QUERY_LIMITED_INFORMATION`，调用前重新读取创建时间与关键标志，随后等待最多 5 秒确认。
- **确认对话框**：按操作类型与等级定制文案；`Caution` 强制结束必须勾选“我已保存工作”才能继续；不出现“不会崩溃”一类绝对表述。
- **本地审计**：每次干预（含拒绝）写入 `InterventionEvents`：时间、目标 `ProcessInstanceKey`、进程名、路径、评估等级、用户选择、结果与 Win32 错误。不保存命令行、环境变量或文档内容。

## 边界与硬性保护（与设计文档一致）

- 执行器只存在于前台 App 进程；Collector IPC 只有只写的 `intervention` 审计追加操作，不含任何终止能力。
- 硬性禁止不可绕过：`IsProcessCritical` 关键进程、PID 0/4、NetScope 自身、其他用户/Session 0、承载 Windows 服务、关键证据缺失（未知即拒绝强制结束）。
- 执行瞬间复核：打开句柄后核对 PID + 创建时间（±2 秒容差）+ 关键标志 + 会话/所有者/服务归属；PID 复用（创建时间变化）直接拒绝且未执行任何操作。
- 不使用 SeDebugPrivilege、不提权、不结束进程树、不结束服务、不支持批量或定时执行；每次操作都来自当次前台点击 + 确认。
- 知识库终止策略（`TerminationKnowledge`，36 条内置进程全覆盖）只作为解释证据与等级上限，必须结合路径（Windows 目录）或有效签名才生效——系统进程名伪装会被降级为“无法判断”。
- 高 CPU、影响排行与异常事件只解释用户动机，不降低安全等级。

## 实现结构

| 层 | 组件 | 说明 |
|---|---|---|
| Core | `InterventionModels`、`ProcessTerminationAdvisor`、`TerminationKnowledge` | 纯规则引擎与模型，可用事实快照测试 |
| Windows | `ProcessSafetyInspector` | 只读事实采集：`PROCESS_QUERY_LIMITED_INFORMATION` + 令牌所有者 + `ProcessIdToSessionId` + SCM 服务索引（30 秒缓存） |
| Windows | `ProcessTerminationExecutor` | 执行 + 复核 + Win32 错误映射 |
| App | 进程详情卡片、确认对话框、执行/结果/刷新 | `App.xaml.cs` 注入检查器与执行器 |
| History | `InterventionEvents` 表 + IPC `intervention` 追加 | 审计随保留期清理 |

## 自动化验收（223/223 通过，原 194 + 新增 29）

- `V11AdvisorTests`（20 项）：五个等级的规则覆盖；关键标志/保留 PID/NetScope 自身禁止；服务宿主、Session 0、其他用户强烈不建议；**未知字段（关键标志查询失败、所有者读取失败、路径缺失）全部收敛到“无法判断”且不允许强制结束**；系统进程名伪装降级；知识库关键进程（Windows 路径验证后）禁止；主窗口/监听端口升级为谨慎；干净第三方“通常可以结束”；未签名不影响系统安全性；高占用不降低等级。
- `V11ExecutorTests`（6 项）：只操作测试自己启动的子进程——真实 `TerminateProcess` 成功并确认退出；无窗口子进程的请求关闭返回“没有可关闭的主窗口”（不冒充成功）；预期创建时间不符（模拟 PID 复用）拒绝且目标不受影响；已退出目标报告无需操作；PowerShell WinForms 测试子进程的正常关闭全链路（WM_CLOSE → 保存退出 → 等待确认）；对测试进程自身 PID 使用伪造创建时间触发身份拒绝。
- `V11StorageTests`（3 项）：审计事件往返保留全部字段；同 ID 重复追加被忽略；保留期清理。
- 视觉 QA：进程详情新增结束建议卡片截图（`design/qa/netscope-performance-termination-v110.png`，含双按钮形态；`processes-v060` 重渲为带卡片的服务宿主形态），并带断言（卡片字段未填充则渲染夹具失败）。

## 实现过程中发现并修复的原生层问题（记录供回溯）

1. `ConvertSidToStringSid` 实际导出为 `W` 后缀且返回 BOOL：初版签名把返回值当字符串指针使用，导致访问违例崩溃测试宿主；已改为经典 DllImport + `out` 接收指针。
2. `OpenSCManager` 同样只导出 `W` 后缀：LibraryImport 不自动加后缀，异常被服务索引捕获吞掉，导致所有评估的“服务归属”永远未知；已改为经典 DllImport。
3. 已终止但句柄未释放的进程：`OpenProcess(PROCESS_TERMINATE)` 返回拒绝而非“已退出”；执行器现在先确认目标实际状态。

## 尚需人工验收（设计 §9/§10，自动化不能替代）

1. Notepad 未保存文本时优先出现保存提示；普通第三方应用显示“通常可以结束/谨慎”并附证据。
2. Explorer、同步工具、虚拟机、数据库显示具体中断影响；System、关键进程、服务宿主、其他用户进程、NetScope 自身均不可操作。
3. Windows 10 1903+ / Windows 11、标准用户与管理员账户下的完整流程；无循环提权提示。
4. 操作完成后进程、端口与连接界面在下一轮刷新内一致。
5. 故障注入：权限变化、目标提前退出、PID 身份变化、历史库不可用时审计降级路径的人工复核。
