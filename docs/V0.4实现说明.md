# V0.4 分析深化：本地开发版

四项功能已接入 Core → Windows 采集 → Collector → SQLite/IPC → WPF 界面。版本号为 0.4.0，尚未创建 GitHub Release。

## 使用入口

升级试运行前需退出旧版 App 和 `NetScope.Collector.exe`（或重启 Windows），再启动本次构建。当前沿用同一用户级采集管道，旧 V0.3 Collector 若仍运行，新界面的 V0.4 指标和连接历史将不可用。

- 性能 → 概览：响应性评分、磁盘合计读写延迟、队列、活跃百分比；悬停响应性文字查看扣分证据。
- 性能 → 事件时间线：新增“相对 CPU 异常”，磁盘事件增加低吞吐卡顿证据。
- 性能 → TCP 连接：查看过去 7 天最近 300 条连接与当前连接，可搜索进程名、PID、IP、端口，并按进程/远端 IP/远端端口分组。选中行查看进程启动时间与结束观察原因，横向滚动查看全部时间列。

## 检测口径

相对检测当前覆盖进程 CPU。按 PID + 启动时间隔离基线，每秒最多学习一次，保留最近 120 个正常样本。至少学习 30 秒后，CPU 同时超过 EWMA + 5 个百分点、中位数 + max(5, 6 × 1.4826 × MAD)、EWMA 的 3 倍，且持续至少 5 秒才生成事件。异常期间冻结基线，恢复后关闭事件并冷却 120 秒。采样中断超过 5 秒或进程重启后重新学习；基线不跨 Collector 重启持久化。常态高占用仍由原有绝对阈值规则处理。

响应性评分是资源压力估计，不是输入延迟实测，也不是故障概率。扣分上限：CPU 35、内存 25、磁盘 30、前台 CPU 5、最近 30 秒用户标记 5。进程 CPU 换算为整机口径后参与评分。磁盘指标缺失时不虚构读数，证据明确说明评分不完整。评分与证据随系统历史保存。

磁盘指标来自英文 PDH 路径 `PhysicalDisk(_Total)`，Windows 负责本地化映射；需要至少两次采样。活跃百分比使用 `100 - % Idle Time`。读/写延迟达到 50ms，或活跃达到 90% 且平均队列达到 2，持续 10 秒可触发压力事件。计数器不可用时显示未采集，保留 V0.3 的进程吞吐规则。指标是物理磁盘合计，不能代替逐盘诊断；进程 I/O 也包含非磁盘操作，所以归因保留“可能”表述。

## 连接历史与数据兼容

连接身份包含进程实例、地址族、本地/远端地址和端口；状态变化更新同一会话。每 2 秒读取完整 TCP 快照，失败时跳过该轮，不把失败当作空表。只跟踪有远端端口的非 Listen TCP 行，不包含 UDP 流量分析。

首次、最后、结束时间均为观察边界。短于采样间隔的连接可能漏记；退出或重启仅表示停止观察，不能断言连接已关闭。连接活动期间每 30 秒写检查点，状态变化和观察结束也写入有界批量队列；异常退出最多损失最近检查点之后的活动时长。内存跟踪最多 10,000 个活动连接，查询最多 500 条，界面默认 300 条。

历史关闭时不写新的连接记录；重新开启后另起观察区间。已有历史仍可查询；数据遵循现有 1/7/14/30 天保留设置。远端 IP 不做 DNS 反查，不主动探测，不上传。

SQLite 使用增量迁移：新增 `TcpConnections` 表和 `SystemSamples.AnalysisJson` 列，保留旧采样，旧记录的新指标为未知。数据库重开时把未结束连接标为“采集器重启，后续状态未知”。
