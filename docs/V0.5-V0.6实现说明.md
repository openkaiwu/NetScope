# NetScope V0.5–V0.6 实现与验收说明

当前本地代码版本为 `0.6.0`，在 V0.4 的相对异常、响应性评分、TCP 连接历史和磁盘增强之上，完成自监控、长期行为分析与可回查 Insights。此次实现未创建 GitHub Release。

## V0.5a：自监控与观察者效应保护

- `CollectorSelfMonitor` 读取 Collector 当前进程累计 CPU、私有提交内存、工作集和 Windows I/O 计数器，以相邻读数换算整机 CPU 百分比及每秒读写量。工作集用于透明展示，50 MB 内存预算按进程独占的私有提交量判断。
- `SelfImpactGuard` 同时检查 CPU、私有内存、磁盘写入与采样周期耗时。连续超预算才降频，避免共享运行时代码页、JIT、GC 或单次数据库提交造成模式振荡。
- 三档采样配置为：Normal（性能 1 秒、端口 2 秒、历史 Top 25）、Reduced（2 秒、5 秒、Top 15）和 Minimal（5 秒、10 秒、Top 8）。严重超预算可直接进入 Minimal；健康样本达到恢复门槛后每次只恢复一级。
- 当前健康状态通过协议 v3 的 `health` 操作提供给前台，并按 30 秒及模式变化写入 SQLite。模式变化写入脱敏日志。自监控或健康历史写入失败不会终止主采样循环。
- 用户标记走独立 IPC 操作，降频只改变后续采样档位，不拒绝或丢弃标记。
- WPF 的进程、事件、连接和 Insights 长列表启用 Recycling 虚拟化。进程路径、文件元数据与双级签名验证只在选中进程后异步执行，并复用既有缓存。

## V0.5b：内存增长与周期行为

- SQLite 按最多约 720 个时间桶/进程实例返回行为分析序列，控制 30 天查询的内存上限。
- `ProcessHistoryPoint` 保留进程名、PID 和启动时间。分析先按实例运行，再按进程名与行为类型保留证据最强的结果，防止 PID 复用或程序重启制造虚假连续趋势。
- 内存增长需要同时满足最小观察窗口、样本数、首尾稳健增长、线性趋势、 R² 和非下降比例。长窗口按总增长门槛自适应最低斜率，使缓慢但累计明显的增长不会被短窗口速率门槛漏掉。
- 周期检测从 CPU/I/O 中位数构造动态活动阈值，把相邻活跃点合并为活动段，再检查活动间隔的范围与离散系数。输出观察窗口、活动次数、周期、阈值、样本证据和置信度。
- 结论统一使用“可能”“趋势”语义。缓存扩张、工作负载变化、更新、同步、索引和遥测均作为替代解释展示。

## V0.6：Insights

- `insights` IPC 操作在 Collector 内读取本地事件、进程分桶、端口会话和 TCP 连接记录，生成卡顿月度统计、重复性能事件、内存增长、周期活动、端口活动与多远端连接六类洞察。
- 支持 7/14/30 天、进程名和洞察类型筛选；返回数量限制在 1–200 条。
- 每条洞察包含时间范围、置信度和证据。基于事件的洞察保留原始事件 GUID；趋势类同时保留 PID、进程启动时间、原始窗口、样本统计和模型指标。
- “查看原始证据”会把事件洞察定位到事件时间线；内存/周期趋势按 PID + 启动时间查询原始窗口，并显示 CPU、私有内存和 I/O 曲线；端口洞察回查对应协议/端口在原始窗口内的占用汇总；连接洞察定位到带进程筛选的 TCP 连接表。样本超过保留期时明确显示原始窗口已不可用。
- 长时间趋势曲线在 SQLite 查询和前台绘制两层都限制为最多 900 点，保留首尾并等距抽样，防止 30 天窗口超过 IPC 消息上限或阻塞界面。
- 空历史、记录关闭后没有足够证据、端口少于 3 个会话或连接少于 5 个不同远端时保持静默，不生成填充式结论。

## 存储与兼容性

- 新增 `CollectorHealth` 表；`SystemSamples`、`ProcessSamples`、`PerformanceEvents`、`PortSessions` 和 `TcpConnections` 保持增量兼容。
- 健康数据随 1/7/14/30 天保留设置清理。端口活动查询按请求窗口裁剪跨边界会话时长。
- IPC 正式管道升级为 `NetScope.Collector.v4`，协议版本为 3，避免缺少私有内存和趋势进程身份字段的旧 App/Collector 混用。
- `Microsoft.Data.Sqlite` 保持 9.0.7，显式覆盖其原生 SQLite 运行库为 `SQLitePCLRaw.lib.e_sqlite3 2.1.13`，移除 2.1.10 的已知高严重性依赖告警。

## 自动化验收

- 173 项 Release 测试覆盖既有 V0.1–V0.4 回归及新增降频滞回、四类预算触发、真实 Collector 自采样、稳定增长、平坦与锯齿缓存、重启隔离、规则与不规则周期、持续高负载、无效样本、洞察阈值/筛选/证据、长曲线 900 点上限、SQLite 聚合/保留期、IPC 往返和 30 天加速模拟。
- WPF 视觉工具生成 1140×720 与 860×580 两种尺寸的性能概览、事件、进程、Insights 和 TCP 连接截图，并检查默认端口工作台。
- 打包脚本会再次执行 Release 测试，再分别发布自包含 App 与 Collector，校验 Collector EXE 存在后生成未签名便携 ZIP；安装了 Inno Setup 时同时生成当前用户安装包。

24 小时真实常驻和整机压力注入需要按墙钟时间单独执行。当前自动化使用 30 天加速时间轴验证算法边界，不能替代真实设备的 24 小时 CPU、内存和磁盘预算结论。
