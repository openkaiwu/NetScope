# 进程终止功能设计（V1.1 受控干预）

状态：设计完成，尚未实现。

## 1. 目标

在“性能 → 进程中心”提供类似任务管理器的结束进程能力，同时先回答两个不同的问题：

1. 结束该进程是否可能造成 Windows 崩溃、注销或关键桌面能力失效；
2. 即使不会造成系统崩溃，是否可能丢失未保存数据、中断下载/同步/虚拟机/服务或影响安全防护。

产品不承诺“安全结束”或“绝不会崩溃”。界面只给出基于当前可验证证据的分级建议，并在执行瞬间重新验证目标身份。任何结束动作必须由用户在前台显式触发，永不自动结束进程。

## 2. 版本位置与范围

按当前顺序推进：

1. V0.4 验收与发布；
2. V0.5a 自监控与 Self Impact Guard；
3. V0.5b 内存泄漏与周期行为检测；
4. V0.6 Insights；
5. V1.0 30 天分析、归因回放与周/月报告；
6. V1.1 受控干预：请求关闭、强制结束、风险建议与本地审计。

V1.1 首版只处理当前用户会话中的单个进程。不结束进程树，不结束 Windows 服务，不提权，不修改启动项，不释放端口，不自动重启应用。上述能力需要另行设计，不能借“结束进程”顺带加入。

## 3. 风险分级

评估结果由 `TerminationAssessment` 表示，包含等级、是否允许请求关闭、是否允许强制结束、证据、预期影响、未知项和建议操作。

| 等级 | 界面用语 | 操作策略 | 典型情况 |
|---|---|---|---|
| Blocked | 禁止结束 | 不显示执行按钮 | `IsProcessCritical=true`、PID 0/4、受保护进程、NetScope 自身/Collector、身份在执行前不一致 |
| StronglyDiscouraged | 强烈不建议 | 首版不允许强制结束；可给替代建议 | Windows 服务宿主、安全软件、登录/桌面/输入/音频关键组件、其他用户或 Session 0 进程 |
| Caution | 可以结束，但可能中断功能或丢失数据 | 优先请求正常关闭；强制结束需第二次确认 | Explorer、索引、同步工具、虚拟机、数据库、开发工具、存在窗口或正在进行明显 I/O 的应用 |
| UsuallyTerminable | 通常可以结束 | 仍优先请求关闭；强制结束保留一次确认 | 同一用户、非关键、非服务、身份可验证的普通第三方应用 |
| Unknown | 无法判断 | 不允许强制结束 | 查询权限不足、启动时间未知、路径/签名/所有者等关键证据缺失 |

“通常可以结束”只表示当前证据下未发现系统崩溃风险，不表示不会丢失应用数据，也不表示进程不会被系统或软件自动拉起。

## 4. 硬性保护规则

以下任一条件成立即禁止执行，不接受用户绕过：

- Windows `IsProcessCritical` 返回关键进程；调用失败也不能降级为“非关键”；
- PID 为 0、4，或目标是 NetScope App / Collector；
- 无法取得 `PROCESS_QUERY_LIMITED_INFORMATION` 并核对创建时间；
- 确认后目标 PID 的创建时间发生变化，说明 PID 已复用；
- 目标属于受保护进程，或无法取得最小的 `PROCESS_TERMINATE` 权限；
- 目标位于其他用户会话、Session 0，或关联 Windows 服务；
- 目标身份、所有者、会话或服务归属处于未知状态。

不使用 `SeDebugPrivilege`，不提供“以管理员身份重试”，不尝试绕过 Windows 的进程保护。权限不足时显示具体原因和可行替代步骤。

知识库中的进程名只作为解释证据，不能单独作为安全结论。恶意程序可以使用系统进程名称；必须同时验证路径、发布者/签名、进程所有者、会话、服务归属、关键标志和进程创建时间。

## 5. 评估输入与决策顺序

`ProcessSafetyInspector` 在用户选中进程时只读采集：

- `ProcessInstanceKey`：PID + Windows 创建时间；
- 完整映像路径及文件元数据缓存；
- Authenticode 状态和发布者；
- `IsProcessCritical`；
- 进程所有者 SID、当前用户 SID、Session ID、完整性级别；
- 是否承载 Windows 服务；
- 是否有可响应的顶层主窗口；
- 是否为前台进程、当前 CPU/内存/I/O、监听端口与活动 TCP 连接；
- 内置知识库建议及过去 7/30 天事件证据。

决策顺序固定为：硬性禁止 → 未知阻断 → 系统/服务高风险 → 数据与功能中断风险 → 普通用户应用。签名有效只能证明发布者和文件完整性，不能直接得出“可以结束”。高 CPU、影响排行或异常事件也只能解释“为什么用户可能想结束”，不能降低安全等级。

## 6. 执行流程

```text
选择进程
  → 只读评估
  → 展示风险、证据与替代建议
  → 用户点击“请求关闭”或“强制结束”
  → 确认对话框展示进程名、PID、路径、风险与数据丢失提示
  → 重新打开句柄并核对 PID + 创建时间 + 关键标志 + 会话/所有者
  → 执行
  → 等待结果并记录本地审计事件
  → 刷新进程、端口、连接和事件视图
```

### 6.1 请求关闭

有主窗口的应用先调用 `CloseMainWindow`，等价于向主窗口发送正常关闭请求。等待最多 10 秒，期间应用可以保存、询问用户或拒绝关闭。请求已发送不等于关闭成功；必须等待进程句柄变为已结束再显示成功。

### 6.2 强制结束

仅对 `Caution` 和 `UsuallyTerminable` 开放。使用最小权限 `PROCESS_TERMINATE | SYNCHRONIZE | PROCESS_QUERY_LIMITED_INFORMATION`，再次读取创建时间和关键标志后调用 `TerminateProcess`，随后等待最多 5 秒确认结果。首版只结束目标进程，不传递到子进程。

强制结束会跳过应用清理，可能丢失数据、破坏正在写入的文件或数据库，并取消未完成 I/O。因此按钮文案必须为“强制结束”，不能用模糊的“结束任务”。如果正常关闭超时，界面可以提供强制结束，但必须重新确认；不能自动升级。

## 7. 界面设计

进程详情增加“操作建议”卡片：

- 顶部显示风险等级和一句结论，例如“通常可以结束，但未保存内容可能丢失”；
- 下方显示 3–6 条直接证据，例如“当前用户进程”“不是 Windows 关键进程”“有效签名：Microsoft Corporation”“承载服务：无”“存在主窗口”；
- 单独列出未知项；有未知项时不显示强制结束按钮；
- 优先显示替代操作，例如“关闭应用窗口”“暂停同步”“从应用内停止虚拟机”“在服务管理器中处理”；
- 展示该进程当前端口、活动连接和最近事件，说明结束后的直接影响；
- `Blocked` 和 `StronglyDiscouraged` 只显示说明与替代建议。

确认对话框不使用统一模板：

- 请求关闭：“允许应用保存并正常退出”；
- 普通强制结束：“未保存内容可能丢失”；
- `Caution` 强制结束：额外列出检测到的具体风险，并要求勾选“我已保存工作”；
- 任何时候都不显示“不会导致电脑崩溃”这类绝对表述。

## 8. 组件边界

### Core

- `TerminationRiskLevel`、`TerminationAssessment`、`TerminationRequest`、`TerminationResult`；
- `ProcessTerminationAdvisor`：纯规则引擎，可用事实快照测试；
- 知识库条目增加结构化字段：`TerminationPolicy`、功能影响和替代操作，保留现有说明文字用于显示。

### Windows

- `ProcessSafetyInspector`：只申请查询权限，采集关键标志、创建时间、所有者、会话和服务归属；
- `ProcessTerminationExecutor`：执行前重新验证，先正常关闭或按请求强制结束，等待并返回明确 Win32 错误；
- 不让 Collector 暴露终止 IPC。执行器只存在于前台 App 进程，减少常驻攻击面。

### App

- 进程详情的建议卡片、正常关闭按钮、强制结束按钮和确认对话框；
- 执行中禁用重复操作；结果按“已退出 / 请求已发送但仍运行 / 权限不足 / 身份已变化 / 操作失败”显示；
- 操作后刷新当前进程、端口和连接数据。

### History

新增 `InterventionEvents`：时间、目标 `ProcessInstanceKey`、进程名、路径摘要、评估等级、用户选择、执行结果和 Win32 错误。不得保存用户文档内容、命令行或环境变量。记录用于问题追踪和报告，不参与自动结束。

## 9. 测试与验收

### 自动测试

- 每个风险等级的规则覆盖，未知字段必须向更保守等级收敛；
- 系统同名伪装、无签名第三方、有效签名第三方、服务宿主、Session 0、其他用户进程；
- 确认前后 PID 相同但创建时间改变时拒绝执行；
- `IsProcessCritical` 查询失败、路径读取失败、服务查询失败时拒绝强制结束；
- 正常关闭成功、拒绝、超时和进程提前退出；
- `TerminateProcess` 成功后等待确认，以及访问拒绝/进程已退出等错误映射；
- 审计写入失败不得把失败的操作显示为成功。

### 隔离集成测试

- 测试专用 GUI 子进程：正常关闭后执行清理并退出；
- 测试专用后台子进程：仅在明确测试参数下允许强制结束；
- PID 复用模拟使用抽象句柄提供方，不尝试真实制造 PID 复用；
- 测试只操作由测试自身启动并持有的子进程；绝不对系统进程做破坏性验证。

### 人工验收

- Notepad 有未保存文本时优先出现保存提示；
- 普通第三方应用显示“通常可以结束”或“谨慎”，并有证据；
- Explorer、同步工具、虚拟机和数据库显示具体中断影响；
- System、关键 Windows 进程、服务宿主、其他用户进程、NetScope 自身均不可操作；
- 操作完成后进程、端口和连接界面在下一轮刷新内一致；
- 无管理员权限的标准用户流程清晰，不出现循环提权提示。

## 10. 发布门槛

V1.1 发布前必须满足：

- 默认不允许强制结束任何证据不完整的目标；
- 关键进程保护和 PID 创建时间复核没有可绕过的 UI 路径；
- 正常关闭为有窗口应用的默认操作；
- 所有执行都来自当次前台点击和确认，不支持定时、规则触发或批量结束；
- 在 Windows 10 1903+、Windows 11、标准用户和管理员账户下完成测试；
- 故障注入覆盖权限变化、目标退出、PID 身份变化和历史库不可用；
- 安全评审确认 Collector IPC 不含终止能力。

## 11. 官方依据

- Microsoft `IsProcessCritical`：以 `PROCESS_QUERY_LIMITED_INFORMATION` 查询 Windows 关键进程。
- Microsoft Process Security and Access Rights：终止只申请 `PROCESS_TERMINATE`，查询只申请有限查询权限；受保护进程受 Windows 访问控制限制。
- Microsoft `Process.CloseMainWindow`：正常关闭允许应用执行保存或拒绝退出，应优先于强制结束。
- Microsoft `TerminateProcess`：强制结束所有线程，不执行常规清理，调用后需要等待确认进程实际退出。
